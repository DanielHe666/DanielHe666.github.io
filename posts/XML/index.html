XML是什么

XML 的全称是 eXtensible Markup Language，即可扩展标记语言。

它是一种类似于 HTML 的标记语言，但它的设计目的完全不同。如果说 HTML 是用来显示数据的（专注于数据的外观和布局），那么 XML 就是用来存储和传输数据的（专注于数据本身的结构和含义）。

核心概念解析

1. 它是什么？（本质）

  • 一种标记语言： 它使用标签（由 < 和 > 包围）来定义数据的结构。
  • 可扩展的： 这是它最关键的特性。HTML 的标签是预定义的（如 <p>, <div>, <h1>），而 XML 允许你自己创建标签，从而为你的数据定义一套专属的结构。例如，你可以定义 <书名>, <价格>, <作者> 这样的标签。
  • 自我描述性： 由于标签名可以自定义且通常具有明确的含义，一份 XML 文档即使没有外部说明，也常常能让人读懂其内容。
  • 纯文本格式： 和 JSON 一样，它是纯文本，不依赖于任何特定的软件或硬件，具有极好的跨平台性。

2. 设计目标

  • 存储和传输数据： 在不同系统、不同平台、不同应用程序之间作为通用的数据交换格式。
  • 作为配置文件： 许多软件和框架使用 XML 文件来存储配置信息。
  • 作为其他语言的基础： 许多重要的网络技术和技术标准都基于 XML 构建，例如： * RSS（ Really Simple Syndication）： 用于内容订阅。 * SOAP（ Simple Object Access Protocol）： 一种 Web 服务协议。 * SVG（ Scalable Vector Graphics）： 用于定义矢量图形。 * XHTML： 更严格、更纯净的 HTML 版本。

XML 的语法规则

XML 的语法非常严格，一个格式良好的 XML 文档必须遵循以下规则：

  1. 必须有根元素： 文档必须有一个唯一的根元素，所有其他元素都是这个根元素的后代。 

    <书架>
    ...所有其他元素...
</书架>

  2. 所有元素必须有关闭标签： * HTML 中你可以写 <br> 或 <p> 而不关闭，但在 XML 中这是不允许的。 * 成对标签： <书名> 必须对应 </书名>。 * 空标签可以自关闭： <页数 />。

  3. XML 标签对大小写敏感： <Book> 和 <book> 是两个不同的标签。

  4. 属性值必须加引号： 

    <书 ISBN="978-7-121-12345-6"> ... </书>

  5. 标签必须正确嵌套： * 正确： <a><b>...</b></a> * 错误： <a><b>...</a></b>

  6. 特殊字符必须转义： * & 必须写成 &amp; * < 必须写成 &lt; * > 必须写成 &gt; * " 必须写成 &quot; * ' 必须写成 &apos;

一个完整的 XML 示例

下面是一个描述书籍信息的 XML 文档：

<?xml version="1.0" encoding="UTF-8"?>
<书架>
    <书 类别="小说">
        <书名>围城</书名>
        <作者>钱钟书</作者>
        <年份>1947</年份>
        <价格 单位="人民币">39.00</价格>
    </书>
    <书 类别="计算机">
        <书名>深入理解计算机系统</书名>
        <作者>Randal E. Bryant</作者>
        <译者>龚奕利</译者>
        <年份>2016</年份>
        <价格 单位="人民币">139.00</价格>
    </书>
</书架>
  • 第一行是 XML 声明，定义了版本和编码。
  • <书架> 是根元素。
  • <书> 是元素，它有一个属性叫“类别”。
  • <书名>、<作者>、<价格> 等是子元素，清晰地描述了数据的各个部分。
  • <价格> 元素自己也有一个“单位”属性。

XML 的相关技术

为了更有效地使用 XML，诞生了一系列相关技术：

  • DTD： 文档类型定义，用于定义 XML 文档的合法构建模块。
  • XSD： XML Schema Definition，是比 DTD 更强大、更常用的定义 XML 结构的方式。
  • XSLT： XML 样式表转换，可以将一个 XML 文档转换为另一种格式（如 HTML, PDF 或另一个 XML）。
  • XPath： 一种在 XML 文档中导航和查询信息的语言。

XML 与 JSON 的对比

这是一个非常常见的问题，因为两者都用于数据交换。

特性 XML JSON
可读性 很好，结构清晰 很好，更简洁
体积 相对较大（标签名重复） 相对较小（无冗余标签）
解析速度 相对较慢（结构更复杂） 相对较快（结构简单）
数据模型 树形结构，支持属性、注释等 键值对集合和数组，更简单
扩展性 极强，有完整的生态（XSD, XSLT等） 较弱，但足以应对大多数场景
与JavaScript 需要专门的 DOM 解析器 天生支持，可直接转换为对象

简单总结选择： * 在Web前端与API通信、配置文件等现代场景中，JSON 因其简洁和高效已成为主流。 * 在企业级应用、复杂文档处理（如 Office文档）、需要严格数据验证和转换的领域，XML 依然占据着重要地位。

总结

XML 是一种强大、灵活、可扩展的标记语言，主要用于以结构化的方式存储和传输数据。它通过自定义标签使数据具有自我描述性，虽然在新项目中常被更轻量的 JSON 取代，但在许多传统和企业级应用场景中，它依然是不可或缺的基石技术。
